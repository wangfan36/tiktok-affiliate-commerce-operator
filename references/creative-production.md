# Creative production and provider controls

Use this reference for scripts, director packages, AI generation, pre-publish
reviews, and competitor-pattern variation.

## Freeze the commercial brief

Before designing or generating, record the exact SKU, US buyer, use occasion,
buying objection, current price, commission, rating, stock evidence, shipping fact,
supported claims, prohibited or unknown claims, available real assets, rights, target
duration, and intended CTA.

Only verified product facts may enter spoken claims or captions. Creative judgments
and operating hypotheses remain labeled.

## First-three-seconds label packet

Align five surfaces around one semantic cluster:

| Surface | Requirement |
|---|---|
| First visible action | Product, problem, result, or use occasion is recognizable |
| Spoken line | Natural buyer/problem/category language |
| On-screen text | One concise audience/pain/benefit phrase |
| Caption/hashtags | Same category and buyer intent, no irrelevant tags |
| Linked SKU | Exact product shown and described |

The opening must be understandable with sound off without covering the product or
proof action. Classification clarity and curiosity must coexist; do not keyword
stuff or rely on an unverified algorithm theory.

## Conversion sequence

Use only the sections the story needs:

```text
Hook → product meaning → visible proof → main objection/offer → product-click CTA
```

For every benefit, define what is visibly proven at that moment. A reaction shot is
not evidence. Preserve real product identity and physical relationships.

Create A/B/C variants around one commercial hypothesis. Keep SKU, body, proof,
duration range, offer, and CTA fixed; change one major variable such as the first
frame, pain wording, or result-first versus pain-first opening. Do not claim a causal
winner when multiple variables changed.

When the local skills are available, use `$tiktok-shop-video-growth` for the growth
gate and `$seedance-ugc-cn-director` for the production-grade director package. Read
their current instructions rather than copying stale parameter assumptions.

## PixVerse default

Use PixVerse when the user asks to generate the approved assets and a configured
PixVerse path is available.

- Use real product images as the identity reference and final packaging layer.
- AI may generate environments, adult actors or hands, and small credible motion.
- Do not rely on generated labels, prices, logos, long captions, or SKU text.
- Split complex demonstrations into short, single-action clips and composite later.
- Record provider, model, duration, resolution, prompt, reference assets, task ID,
  submission time, output URL/path, and status.
- Check current provider capabilities and cost; do not assume model names, reference
  limits, or durations from memory.
- Before paid generation, show the available quote/balance information and obtain
  explicit approval. Before uploading a local file, identify the file and that it
  will leave the machine.
- Do not retry a paid submission when the status is merely pending. Poll the saved
  task ID. On an ambiguous submission response, verify task history before retrying.

## Optional Clipcat adapter

Clipcat remains disabled unless the user explicitly requests it for the current
task. Explicit use does not authorize installation, update, file upload, or spend.

1. Check whether `clipcat` is already installed. Do not run a remote installer or
   `clipcat update` automatically.
2. Inspect `clipcat -h`, the chosen subcommand help, and `clipcat models` before use.
3. Never put an API key in a command argument, response, log, prompt, or saved state.
   If secure authentication is unavailable, stop and ask the user to configure it
   in their own trusted terminal.
4. For local images or video, disclose every file to be uploaded and obtain approval.
5. For a paid command, run `clipcat quote` with the exact submission parameters,
   show model/duration/resolution/total credits, obtain approval, and submit with the
   quoted `--expected-credits` value.
6. Preserve the returned task ID and signed URLs. Query the existing task instead of
   repeating a pending or uncertain paid submission.
7. Use breakdown or generation to create an independent variation. Do not perform
   expression-level copying under the label “replicate.”

## Pre-publish hard gates

Block `ready` when any applies:

- product shown, spoken product, or linked SKU differ;
- price, discount, scarcity, rating, certification, safety, health, or performance
  claim lacks current evidence;
- required affiliate or AI disclosure is missing;
- copyrighted or identity-linked material lacks commercial rights;
- the product or proof action is obscured by overlays, captions, or composited images;
- static presentation violates current Shop requirements;
- dialogue, captions, product visuals, and CTA contradict one another;
- the plan includes fake engagement or deceptive attribution.

Review the actual first 0–3 seconds frame-by-frame with image, audio, text, caption,
and linked SKU together. Give timestamped replacement edits rather than generic
advice.

## Production deliverable

Return:

1. facts, judgments, hypotheses, and unknowns;
2. one-line buyer–problem–product position;
3. exact first-three-seconds label packet;
4. timed Hook → Proof → Offer/Objection → CTA script;
5. product-fact and claim-evidence notes;
6. shot-level asset source and provider prompts;
7. real-product compositing, sound, captions, and safe-area rules;
8. A/B/C variants with one changed variable;
9. provider task and approval plan;
10. pre-publish gate and post-publish measurement plan.
